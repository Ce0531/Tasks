## 一、前后端基础概念
### 1. 前后端连接是什么
前端（浏览器页面）和后端（服务器）通过**网络请求**交换数据
- 前端：页面展示、用户交互、发请求、渲染数据
- 后端：存数据、处理业务逻辑、返回数据
- 完整流程：前端发HTTP请求 → 后端接收处理 → 返回JSON数据 → 前端渲染页面
现在的Vue登录页就是前端，点击登录后需要请求后端接口验证账号密码
### 2. HTTP协议
HTTP是前后端通信的规则，规定了请求和响应的格式
**请求方法（最常用4个）：**
| 方法 | 作用 | 示例 |
| --- | --- | --- |
| GET | 获取数据 | 查询用户列表 |
| POST | 提交数据 | 登录、注册、新增 |
| PUT | 修改数据（全量更新） | 修改用户全部信息 |
| DELETE | 删除数据 | 删除一条记录 |  

**常见状态码：**
| 状态码 | 含义 |
| --- | --- |
| 200 | 请求成功 |
| 400 | 请求参数错误 |
| 401 | 未登录/未授权 |
| 403 | 禁止访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
**请求结构：** 请求行（方法+地址）、请求头（headers）、请求体（data，POST才有）
**响应结构：** 状态行（状态码）、响应头、响应体（data，JSON数据）
### 3. API接口
API = 后端提供给前端调用的接口，每个接口包含：URL地址、请求方法、入参、出参、错误码
**RESTful API 示例：**
```
GET    /api/users        获取用户列表
GET    /api/users/1      获取id为1的用户
POST   /api/users        新增用户
PUT    /api/users/1      修改id为1的用户
DELETE /api/users/1      删除id为1的用户
```
**返回数据格式（统一用JSON）：**
```
{
  "code": 200,
  "message": "成功",
  "data": { "id": 1, "username": "zhangsan" }
}
```
**接口文档：** 后端写的接口说明文件，告诉前端每个接口的地址、方法、参数、返回格式，常用工具：Swagger、Apifox
### 4. 前后端分离
前后端分开开发、独立部署，通过API接口通信
- 前端项目独立部署（如GitHub Pages）
- 后端项目独立部署（提供API服务）
- 两者通过HTTP请求交换JSON数据

## 二、模拟后端：json-server
### 1. 是什么
用一个JSON文件当数据库，快速生成RESTful API的工具。不用写后端代码，就能有一个可以增删改查的假后端，专门用来前端练习接口
### 2. 安装
```
npm install -g json-server
```
### 3. 创建数据文件 db.json
```
{
  "users": [
    { "id": 1, "username": "admin", "password": "123456" },
    { "id": 2, "username": "zhangsan", "password": "111111" }
  ]
}
```
### 4. 启动服务
```
json-server --watch db.json --port 3000
```
启动后访问：

- `http://localhost:3000/users` → 获取所有用户（GET）
- `http://localhost:3000/users/1` → 获取id为1的用户
支持 GET（查）、POST（增）、PUT（改）、DELETE（删），完全模拟真实后端

### 1. axios是什么
- 前端最流行的 **ajax请求库**，用来发送HTTP请求
- 基于 Promise，支持浏览器和Node.js
- 支持请求/响应拦截器、取消请求、自动转换JSON
### 2. 安装与引入
```
npm install axios
```


## 四、axios发送请求
### 1. 基本使用（
**通用写法：**
```
axios({
  method: 'GET',
  url: 'http://localhost:3000/users'
}).then(res => {
  console.log(res.data)
}).catch(err => {
  console.log(err)
})
```
**快捷写法：**
```
// GET请求
axios.get('http://localhost:3000/users')
  .then(res => console.log(res.data))
// POST请求
axios.post('http://localhost:3000/users', {
  username: 'lisi',
  password: '222222'
}).then(res => console.log(res.data))
```
**async/await 写法（推荐，更简洁）：**
```
async function getUsers() {
  try {
    const res = await axios.get('http://localhost:3000/users')
    console.log(res.data)
  } catch (err) {
    console.log(err)
  }
}
```
### 2. 各种请求方法
| 方法 | 写法 | 用途 |
| --- | --- | --- |
| GET | `axios.get(url, config)` | 获取数据 |
| POST | `axios.post(url, data, config)` | 提交数据 |
| PUT | `axios.put(url, data, config)` | 修改数据（全量） |
| PATCH | `axios.patch(url, data, config)` | 修改数据（部分） |
| DELETE | `axios.delete(url, config)` | 删除数据 |
| 通用 | `axios.request(config)` | 通用请求方法 |
**示例：**
```
// 修改用户
axios.put('http://localhost:3000/users/1', {
  username: 'admin_new',
  password: '654321'
})
// 删除用户
axios.delete('http://localhost:3000/users/1')
```

## 五、响应结果与配置管理
### 1. 响应结果结构
请求成功后，`response` 对象的属性：
| 属性 | 说明 |
| --- | --- |
| `response.data` | 后端返回的数据（最常用，就是JSON内容） |
| `response.status` | HTTP状态码（如200、404） |
| `response.statusText` | 状态文本（如OK） |
| `response.headers` | 响应头 |
| `response.config` | 请求的配置信息 |
| `response.request` | 原生请求对象 |
**重点：** 后端返回的数据在 `response.data` 里
请求失败时 `error` 对象：
- `error.response`：有响应但状态码错误（404、500）
- `error.request`：请求发出但没收到响应（网络问题、超时）
- `error.message`：错误信息
### 2. 配置对象（视频07）
| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| `url` | 请求地址 | `'/users'` |
| `method` | 请求方法 | `'get'` |
| `baseURL` | 基础URL，拼在url前面 | `'http://localhost:3000'` |
| `headers` | 请求头 | `{ 'Content-Type': 'application/json' }` |
| `params` | URL查询参数（?后面） | `{ page: 1, size: 10 }` |
| `data` | 请求体数据（POST/PUT用） | `{ username: 'admin' }` |
| `timeout` | 超时时间（毫秒） | `5000` |
| `responseType` | 响应类型 | `'json'`、`'blob'`（下载文件） |
| `withCredentials` | 跨域是否带cookie | `true` |  

**示例：带参数的GET请求**
```
axios({
  method: 'GET',
  url: '/users',
  baseURL: 'http://localhost:3000',
  params: { page: 1, size: 10 },
  timeout: 5000
})
// 实际地址：http://localhost:3000/users?page=1&size=10
```
### 3. 默认配置（视频08）
全局默认配置，所有请求自动生效，不用每个请求重复写：
```
axios.defaults.baseURL = 'http://localhost:3000'
axios.defaults.timeout = 5000
axios.defaults.headers.common['Authorization'] = 'Bearer token'
```
设置后简化请求：
```
axios.get('/users')   // 自动拼上 baseURL
```

## 六、axios进阶用法
### 1. 创建实例
项目需要请求多个不同后端地址时，创建多个实例，每个实例独立配置
```
const request1 = axios.create({
  baseURL: 'http://localhost:3000',
  timeout: 5000
})
const request2 = axios.create({
  baseURL: 'http://localhost:8080',
  timeout: 10000
})
request1.get('/users')    // 请求3000端口
request2.get('/orders')   // 请求8080端口
```
### 2. 拦截器
**请求拦截器：** 请求发送前执行，统一加token、加请求头
```
axios.interceptors.request.use(
  config => {
    config.headers.Authorization = 'Bearer ' + localStorage.getItem('token')
    return config   // 必须return，请求才能继续发
  },
  error => Promise.reject(error)
)
```
**响应拦截器：** 收到响应后执行，统一处理返回数据和错误
```
axios.interceptors.response.use(
  response => response.data,   // 直接返回data，页面不用再写.data
  error => {
    if (error.response.status === 401) {
      alert('登录已过期，请重新登录')
    }
    return Promise.reject(error)
  }
)
```
**移除拦截器：**
```
const myInterceptor = axios.interceptors.request.use(/* ... */)
axios.interceptors.request.eject(myInterceptor)
```
### 3. 取消请求
取消正在进行的请求，用于频繁切换页面、搜索防抖、组件卸载等场景。
```
const controller = new AbortController()

axios.get('/users', { signal: controller.signal })

controller.abort()   // 取消请求
```

## 七、跨域问题
### 1. 同源策略与跨域
浏览器的安全机制：只有**协议、域名、端口**都相同的地址才能互相请求，否则浏览器会拦截响应，这就是**跨域**
例如：
- 前端跑在 `http://localhost:5173`（Vite开发服务器）
- 后端跑在 `http://localhost:3000`（json-server）
- 端口不同 → 跨域 → 浏览器拦截
### 2. 开发环境解决：Vite代理
在 `vite.config.js` 里配置代理，让前端请求通过Vite转发给后端，浏览器以为是同源请求：
```
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:3000',   // 后端地址
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  }
})
```
配置后，前端请求 `/api/users` 会被代理转发到 `http://localhost:3000/users`
### 3. 生产环境解决：后端配置CORS  
后端在响应头里加 `Access-Control-Allow-Origin`，允许指定域名跨域访问。json-server默认自带CORS，真实后端需要后端开发人员配置

## 八、接口调试与工程化
### 1. Network面板调试
浏览器按 `F12` → Network面板，查看每个请求的详细信息：
- 请求URL、方法、状态码
- 请求头、请求参数
- 响应头、响应数据
- 请求耗时
**判断前后端谁的问题：**
| 现象 | 问题在哪 |
| --- | --- |
| 请求没发出去 | 前端（代码没执行或地址错） |
| 状态码400 | 前端（参数格式错） |
| 状态码401/403 | 前端（没带token或权限不足） |
| 状态码404 | 前端或后端（URL错或后端无此接口） |
| 状态码500 | 后端（代码报错） |
| 状态码200但数据错 | 后端（返回数据有问题） |
| CORS报错 | 配置（跨域没解决） |
### 2. Postman / Apifox 接口测试工具
在写前端代码之前，先用工具测试后端接口是否正常：
- 输入URL、方法、参数
- 发送请求，看返回数据
- 接口没问题了再写前端代码
Apifox是国产工具，支持接口文档、Mock、测试一体化，推荐使用
### 3. 接口统一管理（工程化做法）
建 `src/api/` 文件夹，把所有接口请求集中管理，页面只调用函数，不直接写axios
```
// src/api/user.js
import request from '@/utils/request'
// 登录接口
export function login(data) {
  return request.post('/login', data)
}
// 获取用户列表
export function getUserList(params) {
  return request.get('/users', { params })
}
```
页面中使用：
```
import { login } from '@/api/user'

const res = await login({ username: 'admin', password: '123456' })
```
好处：接口变更只改一个地方，不用满项目找
### 4. Mock数据
后端接口还没写好时，前端用假数据先开发，等接口好了再替换
- 简单项目：直接在代码里写死假数据
- 正规项目：用 Apifox Mock 或 json-server

## 九、实践内容
### 实现前后端交互页面
#### 步骤1：启动json-server
```
npm install -g json-server
# 新建 db.json，写入用户数据
json-server --watch db.json --port 3000
```
#### 步骤2：安装axios
```
npm install axios
```
#### 步骤3：封装axios（src/utils/request.js）
```
import axios from 'axios'
const request = axios.create({
  baseURL: 'http://localhost:3000',
  timeout: 5000
})
// 请求拦截器：加token
request.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = 'Bearer ' + token
  return config
})
// 响应拦截器：统一处理
request.interceptors.response.use(
  res => res.data,
  err => {
    console.error('请求错误：', err.message)
    return Promise.reject(err)
  }
)
export default request
```
#### 步骤4：登录页面使用（Login.vue）
```
<template>
  <div>
    <input v-model="form.username" placeholder="用户名" />
    <input v-model="form.password" placeholder="密码" type="password" />
    <button @click="handleLogin">登录</button>
  </div>
</template>
<script setup>
import { ref } from 'vue'
import request from '@/utils/request'
const form = ref({ username: '', password: '' })
const handleLogin = async () => {
  // 前端输入 → 发请求 → 后端返回 → 前端判断
  const users = await request.get('/users', {
    params: {
      username: form.value.username,
      password: form.value.password
    }
  })
  if (users.length > 0) {
    alert('登录成功')
    localStorage.setItem('username', form.value.username)
  } else {
    alert('用户名或密码错误')
  }
}
</script>
```

## 十、思考题

### 1、前后端分离带来哪些好处？有哪些新问题？
**好处：**
1. 分工明确：前端专注交互，后端专注数据和业务
2. 并行开发：约定接口格式后同时开发
3. 多端复用：一套API给Web、App、小程序共用
4. 维护方便：前后端互不影响
5. 性能优化：前端做缓存、按需加载  
   
**新问题：**
1. 跨域：不同端口/域名请求被拦截，需配代理或CORS
2. 联调耗时：需约定接口格式，前后端对接调试
3. 数据格式：需统一返回格式（code、message、data）
4. 安全性：接口暴露在外，需鉴权（token）
5. 调试复杂：出问题要判断前端还是后端的错
### 2、调试前后端交互，先看前端还是后端？依据是什么？
先看浏览器Network面板，通过状态码判断：
| 现象 | 问题在哪 | 依据 |
| --- | --- | --- |
| 请求没发出去 | 前端 | 代码没执行或地址写错 |
| 状态码400 | 前端 | 参数格式错误 |
| 状态码401/403 | 前端 | 没带token或权限不足 |
| 状态码404 | 前端或后端 | URL写错或后端无此接口 |
| 状态码500 | 后端 | 后端代码报错 |
| 状态码200但数据错 | 后端 | 返回数据有问题 |
| CORS报错 | 配置 | 跨域没解决 |
| 请求超时 | 后端或网络 | 后端无响应或网络不通 |
### 3、接口变更了，前端如何更稳妥适配？有没有工程化做法？
**手动适配（简单项目）：** 看接口文档改代码 → 测试确认
**工程化做法（中大型项目）：**
| 做法 | 说明 |
| --- | --- |
| 接口统一管理 | 所有接口放 `src/api/`，改接口只改一处 |
| Mock数据 | 后端没好时先用假数据开发 |
| 接口文档工具 | Swagger、Apifox，前后端共享，变更有通知 |
| TypeScript类型 | 定义接口返回类型，字段变了编译时报错 |
| 接口版本化 | `/api/v1/users`，升级不影响旧版 |
| 自动化测试 | 变更后自动跑测试，发现问题 |
## 十一、难点标注
| 难点 | 理解 |
| --- | --- |
| 前后端分离 | 前后端分开，通过API接口交换数据 |
| 跨域 | 浏览器安全机制，不同域名/端口请求被拦截，需代理或CORS |
| baseURL | 基础地址，设置后只写后半段路径，自动拼接 |
| params vs data | params是URL?后参数（GET用），data是请求体（POST用） |
| 响应拦截器返回data | return response.data后，页面直接拿到数据，不用再写.data |
| 请求拦截器加token | 所有请求自动带登录凭证，不用每个手动加 |
| axios实例 | 多个实例不同配置，适配多个后端服务 |
| json-server | JSON文件模拟后端，练习接口的神器 |
| 状态码判责任 | 4xx前端问题，5xx后端问题 |
| 取消请求 | 组件卸载或频繁请求时取消旧请求，避免浪费和报错 |
| Vite代理 | 开发环境解决跨域，请求通过Vite转发给后端 |
| 接口统一管理 | 所有接口放src/api，变更只改一处 |

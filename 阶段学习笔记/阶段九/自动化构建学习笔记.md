## 一、构建工具概述
### 1. 什么是构建工具
构建工具是把**源代码**自动转换成**可运行的工程产物**的工具
简单说：写的 Vue 组件、SCSS 样式、ES6+ 语法，浏览器不能直接运行，需要构建工具帮你翻译成浏览器能识别的 HTML、CSS、JS，并且打包成一个或多个文件
之前用的 `npm run build` 生成 `dist` 文件夹，就是构建工具（Vite）在工作
### 2. 构建工具主要解决什么问题
| 问题 | 说明 |
| --- | --- |
| 语法转换 | ES6+ 转 ES5、TypeScript 转 JS、SCSS/Less 转 CSS |
| 模块打包 | 把多个 JS 文件合并成一个或几个文件，减少请求 |
| 资源处理 | 图片压缩、字体处理、CSS 前缀自动补全 |
| 代码压缩 | 去掉空格、注释，缩短变量名，减小体积 |
| 热更新 | 开发时改代码，浏览器自动刷新，不用手动 F5 |
| 环境区分 | 开发环境和生产环境用不同的配置 |

## 二、自动化构建
自动化构建 = 用工具自动完成重复的构建任务（压缩、合并、转换等），不用手动一个个处理
### （一）npm script
#### 1. 是什么
npm script 就是 `package.json` 里的 `scripts` 字段，通过 `npm run 名字` 来执行命令
```
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```
#### 2. 特点
- **零依赖**：npm 自带，不需要额外安装任何工具
- **简单直接**：就是执行命令行命令
- **支持串联**：用 `&&` 连接多个命令，前一个成功才执行后一个
```
"scripts": {
  "build": "npm run clean && npm run compile",
  "clean": "rm -rf dist",
  "compile": "tsc"
}
```
#### 3. 适用场景
- 简单的项目，只需要执行几条命令
- 调用其他构建工具（如 `vite build`、`webpack`）
- 作为项目统一的命令入口
### （二）gulp
#### 1. 是什么
gulp 是一个**基于流的自动化构建工具**，用 JavaScript 代码来描述构建流程
需要写一个 `gulpfile.js` 配置文件，定义任务
#### 2. 安装
```
npm install -g gulp-cli       # 全局安装命令行工具
npm install --save-dev gulp   # 项目内安装
```
#### 3. 简单示例（gulpfile.js）
```
const gulp = require('gulp')
const uglify = require('gulp-uglify')   // JS 压缩插件
const concat = require('gulp-concat')   // 文件合并插件

// 定义一个任务：压缩并合并 JS
gulp.task('scripts', function () {
  return gulp.src('src/js/*.js')     // 读取源文件
    .pipe(concat('all.js'))          // 合并成一个文件
    .pipe(uglify())                  // 压缩
    .pipe(gulp.dest('dist/js'))      // 输出到目标目录
})
```
运行任务：
```
gulp scripts
```
#### 4. 特点
- **基于流（pipe）**：文件像流水一样经过一个个插件处理
- **插件生态丰富**：压缩、合并、重命名、加前缀等都有对应插件
- **代码即配置**：用 JS 写构建流程，灵活度高
- 适合**文件处理型**任务：批量压缩图片、合并 CSS、转换格式等
### （三）npm script 与 gulp 的区别
| 对比 | npm script | gulp |
| --- | --- | --- |
| 本质 | 执行命令行命令 | 用代码写构建流程 |
| 额外安装 | 不需要，npm 自带 | 需要安装 gulp 和插件 |
| 配置方式 | package.json 里写命令 | gulpfile.js 里写代码 |
| 灵活度 | 低，只能串联命令 | 高，可以写复杂逻辑 |
| 适用场景 | 简单任务、调用其他工具 | 文件批量处理、复杂构建流程 |
| 学习成本 | 极低 | 中等（需了解流和插件） |

## 三、模块化打包工具
模块化打包 = 把项目里的各种模块（JS、CSS、图片等）按照依赖关系打包成浏览器能运行的文件
### （一）Webpack
#### 1. 是什么
Webpack 是目前**最主流**的前端模块打包工具，Vue CLI、Create React App 底层都是 Webpack
核心理念：**一切皆模块**。JS、CSS、图片、字体、HTML 都可以当作模块处理。
#### 2. 核心概念
| 概念 | 说明 |
| --- | --- |
| entry（入口） | 从哪个文件开始打包，默认 `src/index.js` |
| output（输出） | 打包后的文件放到哪里、叫什么名字 |
| loader（加载器） | 处理非 JS 文件，如 babel-loader 转 ES6、css-loader 处理 CSS |
| plugin（插件） | 执行更广泛的任务，如压缩、提取 CSS、生成 HTML |
| mode（模式） | development（开发）或 production（生产），自动优化 |
#### 3. 简单配置（webpack.config.js）
```
const path = require('path')
module.exports = {
  entry: './src/index.js',          // 入口
  output: {                         // 输出
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist')
  },
  module: {
    rules: [
      { test: /\.css$/, use: ['style-loader', 'css-loader'] }  // 处理 CSS
    ]
  },
  mode: 'production'
}
```
#### 4. 特点
- 生态最丰富，loader 和 plugin 最多
- 功能强大，能处理各种资源
- 配置相对复杂
- 适合**复杂的大型单页应用（SPA）**
### （二）Rollup
#### 1. 是什么
Rollup 是一个专注于 **JavaScript 模块**的打包工具，Vue、React、Vue Router 等知名库的源码就是用 Rollup 打包的
#### 2. 核心特点
- **Tree-shaking（摇树优化）**：自动剔除没有被使用的代码，打包体积小
- 配置简单
- 专注 JS，对 CSS、图片等非 JS 资源支持较弱
- 输出格式支持多种：ES Module、CommonJS、UMD、IIFE
#### 3. 简单配置（rollup.config.js）
```
export default {
  input: 'src/index.js',          // 入口
  output: {
    file: 'dist/bundle.js',       // 输出
    format: 'es'                  // 输出格式：ES Module
  }
}
```
#### 4. 适用场景
- 打包**JavaScript 库（library）**，如组件库、工具函数库
- 对打包体积要求高的项目
- 不需要处理大量非 JS 资源的项目
### （三）Parcel
#### 1. 是什么
Parcel 是一个**零配置**的打包工具，开箱即用，不需要写配置文件
#### 2. 特点
- **零配置**：不需要写 config 文件，直接指定入口文件就行
- 自动处理各种资源：JS、CSS、图片、TypeScript 都能识别
- 构建速度快（多核并行处理）
- 内置开发服务器和热更新
#### 3. 使用方式
```
npm install -g parcel-bundler
parcel index.html    # 直接打包，不需要配置文件
```
#### 4. 适用场景
- 快速原型开发
- 小型项目
- 不想写配置的开发者
### （四）Snowpack
#### 1. 是什么
Snowpack 是一个基于**浏览器原生 ESM（ES Modules）**的构建工具
核心理念：开发时不打包，利用浏览器原生支持的 ES Module，每个文件单独提供给浏览器，改哪个文件就更新哪个，不需要重新打包整个项目
#### 2. 特点
- 开发服务器启动**极快**（不需要打包）
- 热更新快（只更新改动的文件）
- 生产构建时可以调用 Webpack 或 Rollup
- 适合现代浏览器项目
#### 3. 现状
Snowpack 的理念被 **Vite** 吸收并超越，Vite 开发模式就是类似的思路（不打包，用原生 ESM），现在 Snowpack 已经不太活跃了，新项目更推荐 Vite
### （五）四者区别对比
| 对比 | Webpack | Rollup | Parcel | Snowpack |
| --- | --- | --- | --- | --- |
| 定位 | 通用模块打包器 | JS 库打包器 | 零配置打包器 | ESM 开发构建工具 |
| 配置 | 复杂 | 简单 | 零配置 | 简单 |
| 非JS资源 | 支持最好 | 较弱 | 自动支持 | 支持 |
| Tree-shaking | 支持 | 优秀 | 支持 | 支持 |
| 开发速度 | 中等 | 中等 | 快 | 极快 |
| 生态 | 最丰富 | 较丰富 | 一般 | 一般 |
| 适用场景 | 大型应用 | JS 库/组件库 | 快速原型/小项目 | 现代浏览器开发 |
| 现状 | 主流 | 库打包首选 | 小众 | 已被 Vite 超越 |

## 四、打包体积相关因素
### 体积变大的原因
| 因素 | 说明 |
| --- | --- |
| 第三方依赖多 | 引入了大量 npm 包，每个包都有体积 |
| 未做 Tree-shaking | 没有剔除未使用的代码，全量打包 |
| 未压缩 | 没有去掉空格、注释、缩短变量名 |
| 开发依赖混入 | 把 devDependencies 里的工具也打进了生产包 |
| Source map 内联 | 把 source map 直接写进了 JS 文件 |
| 图片未优化 | 大图直接打包，没有压缩或转 WebP |
| 未代码分割 | 所有代码打成一个大文件，首屏加载慢 |
| 全量引入库 | 比如 `import _ from 'lodash'` 引入整个库，而不是按需引入 |
### 体积变小的方法
| 方法 | 说明 |
| --- | --- |
| Tree-shaking | 自动删除未使用的代码（Rollup、Webpack 生产模式支持） |
| 代码压缩 | 使用 terser 等工具压缩 JS，去掉空格注释 |
| 按需引入 | 只引入用到的部分，如 `import { debounce } from 'lodash-es'` |
| 代码分割 | 把代码拆成多个 chunk，按需加载，首屏只加载必要的 |
| 图片优化 | 压缩图片、用 WebP 格式、小图转 base64 |
| externals | 把大型库（如 Vue、React）配置为外部依赖，不打进包里，用 CDN 引入 |
| 生产模式 | 用 `mode: 'production'`，自动开启压缩和优化 |

## 六、思考题
### 1、：构建工具主要解决了哪些问题？如果不用构建工具，项目会遇到哪些困难？
**主要解决的问题：**
- 语法转换（ES6+ 转 ES5、TypeScript 转 JS、SCSS 转 CSS）
- 模块打包（多个文件合并，减少请求）
- 资源处理（图片压缩、CSS 前缀补全）
- 代码压缩（去空格、注释，缩短变量名）
- 热更新（改代码自动刷新）
- 环境区分（开发/生产不同配置）
**不用构建工具的困难：**
- ES6+ 语法老浏览器不支持，需手动转写
- 多个 JS 文件要手动按顺序用 script 标签引入，容易出错
- 代码不能压缩，体积大，加载慢
- 改一次代码要手动刷新浏览器，开发效率低
- SCSS、TypeScript 等无法直接使用
---
### 2、：Webpack 和 Rollup 的侧重点有什么不同？什么场景适合哪个？
**Webpack：**
- 侧重**应用开发**
- 一切皆模块，能处理 JS、CSS、图片等各种资源
- 功能全面但配置复杂
- 适合大型单页应用（SPA）
**Rollup：**
- 侧重**库打包**
- 专注 JS 模块，Tree-shaking 优秀，输出体积小
- 配置简单
- 适合打包组件库、工具函数库
**选型：** 做网站/应用用 Webpack（或 Vite），写开源库/组件库用 Rollup
---
### 3、：打包后体积变大/变小通常与哪些因素有关？
**变大的因素：**
- 第三方依赖引入过多
- 未做 Tree-shaking，未使用的代码也被打包
- 未开启代码压缩
- 开发依赖（devDependencies）混入生产包
- Source map 内联到 JS 文件中
- 图片未压缩优化
- 未做代码分割，所有代码打成一个大文件
- 全量引入第三方库而非按需引入
**变小的方法：**
- 开启 Tree-shaking 剔除无用代码
- 生产模式下自动压缩代码
- 按需引入第三方库
- 代码分割，按需加载
- 图片压缩、转 WebP、小图转 base64
- 大型库配置 externals，用 CDN 引入
- 使用生产模式构建

## 七、难点标注
| 难点 | 一句话理解 |
| --- | --- |
| 构建 vs 打包 | 构建是大概念（转换+压缩+打包），打包是构建的一部分（合并文件） |
| loader vs plugin | loader 处理文件内容（转译），plugin 做更广的任务（压缩、生成文件） |
| Tree-shaking | 像摇树一样把没用的代码（枯叶）摇掉，只保留用到的 |
| 自动化构建 vs 模块化打包 | 前者侧重任务自动化（gulp），后者侧重模块依赖合并（webpack） |
| 开发模式 vs 生产模式 | 开发模式不压缩、有 source map、好调试；生产模式压缩优化、体积小 |
| ESM 原生加载 | 现代浏览器直接支持 import/export，不需要打包就能运行，Snowpack/Vite 利用了这一点 |
| 代码分割 | 把大文件拆成小文件，按需加载，首屏更快 |
| Vite 是什么 | Vite 开发时用原生 ESM（类似 Snowpack），生产构建用 Rollup，是目前最推荐的构建工具 |

## 八、总结
### 构建工具分类速查
```
构建工具
├── 自动化构建（任务自动化）
│   ├── npm script    → 简单命令，零依赖
│   └── gulp          → 代码写流程，文件处理
│
└── 模块化打包（依赖合并）
    ├── Webpack       → 大型应用，一切皆模块
    ├── Rollup        → JS 库，Tree-shaking 强
    ├── Parcel        → 零配置，快速原型
    ├── Snowpack      → 原生 ESM，已被 Vite 超越
    └── Vite          → 开发用 ESM + 生产用 Rollup，目前最推荐
```
### 常用
```
# npm script
npm run dev          # 开发
npm run build        # 打包
npm run preview      # 预览
# gulp
npm install -g gulp-cli   # 安装
gulp <task-name>          # 执行任务
# webpack
npx webpack               # 打包
npx webpack --mode production  # 生产模式打包
# rollup
npx rollup -c             # 按配置文件打包
# parcel
npx parcel index.html     # 零配置开发
npx parcel build index.html  # 零配置打包
```
